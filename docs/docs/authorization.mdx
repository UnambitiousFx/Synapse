# Authorization

`UnambitiousFx.Synapse.Authorization` authorizes requests inside the pipeline, so the same rules apply whether a request comes from an HTTP endpoint, an MCP tool, a background job or a CLI. Endpoint-level ASP.NET Core policies do not cover those other transports.

```bash
dotnet add package UnambitiousFx.Synapse.Authorization
```

## Setup

Implement `ICurrentPrincipal` over your caller's identity, register it, then call `AddSynapseAuthorization`:

```csharp
public sealed class HttpCurrentPrincipal(IHttpContextAccessor accessor) : ICurrentPrincipal
{
    private ClaimsPrincipal? User => accessor.HttpContext?.User;

    public bool IsAuthenticated => User?.Identity?.IsAuthenticated == true;
    public string? Id => User?.FindFirstValue(ClaimTypes.NameIdentifier);
    public bool HasScope(string scope) => User?.HasClaim("scope", scope) == true;
    public bool IsInRole(string role) => User?.IsInRole(role) == true;
}

services.AddHttpContextAccessor();
services.AddScoped<ICurrentPrincipal, HttpCurrentPrincipal>();
services.AddSynapse(cfg => cfg.AddRegisterGroup(new RegisterGroup()));
services.AddSynapseAuthorization(o =>
{
    o.QueryScope = "read";              // default
    o.CommandScope = "write";           // default
    o.Policy<LoanAccessPolicy>();       // IResourceAccessPolicy, scoped
    o.DenialRecorder<AuditDenials>();   // IAuthorizationDenialRecorder, scoped, optional
});
```

## The checks

Four behaviors run on every `Result` and `Result<T>` request, in a fixed order. The first one that denies the request short-circuits the pipeline: the handler and the later checks do not run.

| Order | Behavior | Applies to | Denial |
|---|---|---|---|
| `AuthorizationBehaviorOrder.Actor` (1000) | `ActorAuthorizationBehavior` | every request | `UnauthenticatedFailure` when `ICurrentPrincipal.IsAuthenticated` is false |
| `AuthorizationBehaviorOrder.Role` (2000) | `RoleAuthorizationBehavior` | `IRequiresRole` | `UnauthorizedFailure` when the caller is not in `Role` |
| `AuthorizationBehaviorOrder.Scope` (3000) | `ScopeAuthorizationBehavior` | queries, commands, `IRequiresScope` | `UnauthorizedFailure` when the caller lacks the scope |
| `AuthorizationBehaviorOrder.Resource` (4000) | `ResourceAuthorizationBehavior` | `IResourceScoped` | `UnauthorizedFailure` when the policy says no |

The positions are the numeric `IOrderedPipelineBehavior.Order`: after the built-in `First` behaviors (CQRS enforcement, outbox discard) and before validation (`Last`). The gaps let you put your own behavior between two checks, for example `Order => AuthorizationBehaviorOrder.Resource - 1` to load a tenant before the resource check.

## Markers

```csharp
// Default scope: a query needs QueryScope ("read").
public sealed record GetLoan(Guid Id) : IQuery<LoanView>, IResourceScoped
{
    public string ResourceId => Id.ToString();
    public string Access => "read";
}

// Default scope: a command needs CommandScope ("write"), plus the admin role.
public sealed record PurgeLoans : ICommand, IRequiresRole
{
    public string Role => "admin";
}

// Its own scope instead of "read".
public sealed record ExportLoans : IQuery<byte[]>, IRequiresScope
{
    public string Scope => "loans:export";
}
```

- **Scopes.** A request that implements `IRequiresScope` needs its `Scope`. Otherwise an `IQuery<T>` needs `QueryScope` and an `ICommand` / `ICommand<T>` needs `CommandScope`. A plain `IRequest` that declares no scope needs none.
- **Turning the default off.** `o.DisableDefaultScopes()` (or setting `QueryScope` / `CommandScope` to `null`) stops the query / command rule. Requests that implement `IRequiresScope` are still checked.
- **Roles.** `IRequiresRole.Role` is checked with `ICurrentPrincipal.IsInRole`.

## Resource policy

Only the policy is application-specific: who may access which resource.

```csharp
public sealed class LoanAccessPolicy(LoansDbContext db) : IResourceAccessPolicy
{
    public async ValueTask<bool> IsAllowedAsync(ICurrentPrincipal principal, IResourceScoped request,
        CancellationToken cancellationToken = default)
    {
        var loanId = Guid.Parse(request.ResourceId);
        return await db.Loans.AnyAsync(l => l.Id == loanId && l.OwnerId == principal.Id, cancellationToken);
    }
}
```

`request` is the request itself, so you can pattern-match it to read more than `ResourceId` and `Access`. Without a registered policy, every `IResourceScoped` request is denied: the behavior fails closed.

## Recording denials

Every denial is passed to each registered `IAuthorizationDenialRecorder` before the failure is returned:

```csharp
public sealed class AuditDenials(ILogger<AuditDenials> logger) : IAuthorizationDenialRecorder
{
    public ValueTask RecordAsync(AuthorizationDenial denial, CancellationToken cancellationToken = default)
    {
        logger.LogWarning("{Request} denied for {Principal}: {Reason} {Requirement} {Resource}",
            denial.Request.GetType().Name, denial.PrincipalId, denial.Reason, denial.Requirement, denial.ResourceId);
        return ValueTask.CompletedTask;
    }
}
```

`AuthorizationDenial` carries the request, the `Reason` (`Unauthenticated`, `MissingRole`, `MissingScope`, `ResourceAccessDenied`), the caller's `Id`, the missing role, scope or access in `Requirement`, and the `ResourceId` for resource denials.

## HTTP status codes

The failures are the typed ones from `UnambitiousFx.Functional`, so [`IHttpInvoker` / `IMvcInvoker`](./aspnetcore) return a denial status instead of a 500. The default `DefaultFailureHttpMapper` maps `UnauthorizedFailure` to **401** and `UnauthenticatedFailure` to **403**. For the conventional split (401 for anonymous callers, 403 for authenticated callers who lack access), register a mapper before `AddSynapseAspNetCore`:

```csharp
public sealed class AuthorizationStatusMapper : IFailureHttpMapper
{
    private readonly DefaultFailureHttpMapper _default = new();

    public FailureHttpResponse? GetFailureResponse(IFailure failure) => failure switch
    {
        UnauthenticatedFailure => Problem(StatusCodes.Status401Unauthorized, failure),
        UnauthorizedFailure => Problem(StatusCodes.Status403Forbidden, failure),
        _ => _default.GetFailureResponse(failure)
    };

    private static FailureHttpResponse Problem(int status, IFailure failure) => new()
    {
        StatusCode = status,
        Body = new ProblemDetails { Status = status, Detail = failure.Message }
    };
}

builder.Services.AddSingleton<IFailureHttpMapper, AuthorizationStatusMapper>();
builder.Services.AddSynapseAspNetCore(); // TryAddSingleton: keeps the mapper above
```

## Limits

- Every request needs an authenticated caller. There is no marker yet for requests that anonymous callers may send.
- Stream requests (`IStreamRequest<T>`) and events are not authorized.
- The behaviors are registered as open generics, so this package is not Native-AOT compatible.

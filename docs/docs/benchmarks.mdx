# Benchmarks

Synapse is built for low latency and low allocations on the hot path. This page compares it against two popular in-process mediators:

- **[MediatR](https://github.com/jbogard/MediatR)** — reflection-based, the de-facto standard.
- **[Mediator (martinothamar)](https://github.com/martinothamar/Mediator)** — source-generated, MediatR-like API.

All three run the same scenarios from a single [BenchmarkDotNet](https://benchmarkdotnet.org/) suite in `benchmarks/SynapseBenchmark`. Numbers are reproducible — see [Running the benchmarks](#running-the-benchmarks) below.

:::note
Benchmarks measure dispatch overhead only — handlers are no-ops (a sum, or `Task.CompletedTask`). Real applications are dominated by handler work (I/O, DB), so these differences matter most in high-throughput, fan-out, or allocation-sensitive paths.
:::

## Environment

```
BenchmarkDotNet v0.15.8, macOS 27.0 (26A428) [Darwin 27.0.0]
Apple M5 Pro, 18 logical / 18 physical cores
.NET SDK 10.0.401, .NET 10.0.12, Arm64 RyuJIT
```

Lifetimes: Synapse and MediatR use their defaults; **Mediator is registered as `Transient`** to mirror MediatR's transient handlers for an apples-to-apples DI cost. Mediator's recommended `Singleton` lifetime would lower its numbers further.

## Results

Lower is better. **Ratio** is relative to Synapse (baseline `1.00`); **Alloc** is bytes allocated per operation.

### Send — request with response

| Library | Mean | Ratio | Allocated |
|---|---:|---:|---:|
| Mediator | 24.8 ns | 0.95 | 88 B |
| **Synapse** | **26.2 ns** | **1.00** | **72 B** |
| MediatR | 32.4 ns | 1.24 | 200 B |
| _Synapse (direct handler)_ | _6.5 ns_ | _0.25_ | _72 B_ |

### Send — request without response (void)

| Library | Mean | Ratio | Allocated |
|---|---:|---:|---:|
| **Synapse** | **20.1 ns** | **1.00** | **0 B** |
| Mediator | 27.3 ns | 1.36 | 88 B |
| MediatR | 37.3 ns | 1.85 | 128 B |
| _Synapse (direct handler)_ | _3.7 ns_ | _0.18_ | _0 B_ |

Synapse allocates **zero bytes** dispatching a void request.

### Publish — one event, 5 handlers

| Library | Mean | Ratio | Allocated |
|---|---:|---:|---:|
| Mediator | 93.2 ns | 0.72 | 184 B |
| **Synapse** | **129.2 ns** | **1.00** | **520 B** |
| MediatR | 362.6 ns | 2.81 | 2088 B |

Mediator's source-generated fan-out leads here; both beat MediatR by a wide margin.

### Pipeline — request through 1 behavior

| Library | Mean | Ratio | Allocated |
|---|---:|---:|---:|
| **Synapse** | **24.3 ns** | **1.00** | **72 B** |
| Mediator | 37.7 ns | 1.55 | 240 B |
| MediatR | 63.5 ns | 2.61 | 440 B |

### Pipeline — request through 3 behaviors

| Library | Mean | Ratio | Allocated |
|---|---:|---:|---:|
| **Synapse** | **27.9 ns** | **1.00** | **72 B** |
| Mediator | 58.0 ns | 2.08 | 496 B |
| MediatR | 91.9 ns | 3.29 | 728 B |

Synapse's pipeline allocation stays **flat at 72 B** regardless of behavior count, thanks to its cached, pre-composed delegate chain — competitors grow per added behavior.

## Takeaways

- **Pipelines** — Synapse is fastest and flat-allocating; the gap widens as behaviors stack.
- **Send (response)** — Mediator edges ahead on raw speed; Synapse allocates less.
- **Send (void)** — Synapse beats Mediator (20.1 vs 27.3 ns) and allocates nothing.
- **Publish** — Mediator's generated fan-out wins; Synapse is ~2.8× faster than MediatR.
- All three vastly outperform reflection-based MediatR on both time and allocations.

Pick based on your workload: pipeline-heavy / allocation-sensitive favors Synapse; raw publish throughput favors Mediator.

## Endpoints — adapter overhead

A separate benchmark, `EndpointDispatchBenchmark`, measures what the
[Endpoints](./endpoints/index.mdx) package costs on top of a hand-written Minimal API route. Both
sides share the exact same host — same handler, same source-generated `JsonSerializerContext`, same
`AddSynapseAspNetCore` / `AddSynapse` wiring, same three-argument `IHttpInvoker.InvokeAsync` call.
The **only** difference is how the route is mapped: a hand-rolled `MapGet`/`MapPost` lambda versus
`MapEndpoint<T>()` going through the generated binder.

Each arm is a full in-memory HTTP round-trip through `Microsoft.AspNetCore.TestHost` — request
parsing, routing, model binding, serialization, the lot. That means:

:::note
Absolute times here are dominated by the TestServer pipeline, not by dispatch, and are **noisy** —
BenchmarkDotNet flags the distributions as multimodal and the standard deviation approaches the mean.
The number that reproduces run to run is **allocation**. Read this table for the allocation delta,
not for nanosecond-precise timings.
:::

Baseline is `HandWrittenLambda`. Allocated is per request; **Alloc Ratio** is relative to the
hand-written equivalent.

| Arm | Allocated | Alloc Ratio | What it isolates |
|---|---:|---:|---|
| `HandWrittenLambda` (GET) | 9.41 KB | 1.00 | Minimal API lambda, route-only bind — baseline |
| `SynapseEndpoint` (GET) | 9.52 KB | 1.01 | `Endpoint<T,R>` via the generated binder |
| `RawEndpointHandWrittenBinding` (GET) | 9.52 KB | 1.01 | Low-level `BoundEndpoint<T,R>`, `BindAsync` by hand |
| `SynapseEndpointWithHooks` (GET) | 10.59 KB | 1.13 | Both lifecycle hooks overridden — the cost of the seam |
| `SynapseEndpointWithProcessors` (GET) | 10.63 KB | 1.13 | One pre- and one post-processor, resolved per request |
| `SynapseInlineEndpoint` (GET) | 8.60 KB | 0.91 | Endpoint answers itself, no mediator round-trip |
| `SynapseEndpointWithScalarQuery` (GET) | 9.56 KB | 1.02 | Scalar query value — fixes the query-parsing cost |
| `SynapseEndpointWithCollectionQuery` (GET) | 10.16 KB | 1.08 | Repeated query key into an array; compare against the scalar arm |
| `HandWrittenLambdaWithJsonBody` (POST) | 11.53 KB | 1.22 | Minimal API lambda reading a JSON body |
| `SynapseEndpointWithJsonBody` (POST) | 11.69 KB | 1.24 | Generated binder's `ReadJsonBodyAsync` path |

The generated adapter adds **~0.1–0.15 KB per request (~1%)** over the hand-written route, and no
extra Gen0 pressure. On time, the endpoint arm sits inside the hand-written arm's error bars across
repeated runs — the adapter has no dispatch cost you can measure above the HTTP pipeline it runs in.
Opting into lifecycle hooks or processors costs about 1.1 KB (~13%) and roughly 0.4 µs per request;
collecting a repeated query key adds about 0.6 KB over a scalar query value. An inline endpoint that
skips the mediator round-trip allocates ~0.9 KB less than the dispatched one.
The high-level and low-level tiers allocate identically, as expected: the high level *is* the low
level with its `BindAsync` generated.

Environment: same machine and runtime as above.

## Running the benchmarks

```bash
cd benchmarks/SynapseBenchmark
dotnet run -c Release                 # full suite, all classes
dotnet run -c Release -- --filter '*Pipeline*'          # one category
dotnet run -c Release -- --filter '*EndpointDispatch*'  # the Endpoints adapter benchmark
```

The mediator comparison is `SynapseVsMediatorsBenchmarks`; the Endpoints adapter overhead is
`EndpointDispatchBenchmark`; context propagation is `PropagationBenchmarks`. Results land in
`BenchmarkDotNet.Artifacts/results/`.

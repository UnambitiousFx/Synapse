# Endpoints

`UnambitiousFx.Synapse.Endpoints` turns an HTTP route into a class. For the common case that is the
whole endpoint — one attribute, one class declaration, no method body:

```csharp
public sealed record GetTaskQuery(Guid TaskId) : IRequest<TaskDto>;

[Get("/tasks/{taskId:guid}")]
public sealed class GetTaskEndpoint : Endpoint<GetTaskQuery, TaskDto>;
```

That is a complete, working `GET /tasks/{taskId}`. The route value is bound to `TaskId`, the query is
dispatched through the mediator, the handler's result is written as `200 OK` with the `TaskDto` as the
JSON body, and a bad `taskId` answers `400` — all generated at compile time.

It sits on top of `IHttpInvoker` (see [ASP.NET Core Integration](../aspnetcore.mdx)). The invoker still
does the dispatch and the failure mapping; this package removes the boilerplate around calling it.

---

## Which level do you want?

The package has **two levels**, and this is the only decision you need to make before reading
anything else. The question is not "how complicated is my endpoint" — it is **"is this route a
command or a query?"**

<div className="row">
<div className="col col--6">

### The high level

**The route *is* a message.** You declare the message and the endpoint; the analyzer writes the
binding.

```csharp
[Post("/tasks")]
public sealed class CreateTaskEndpoint
    : Endpoint<CreateTaskCommand, TaskCreated>;
```

Use it for the CRUD and query surface of an application — which in practice is almost everything.

**[Start the high-level guide →](./high-level/overview.mdx)**

</div>
<div className="col col--6">

### The low level

**The route is about the HTTP exchange itself.** You get the `HttpContext` and return an `IResult`.

```csharp
[Get("/health")]
public sealed class HealthEndpoint : RawEndpoint
{
    public override ValueTask<IResult> HandleAsync(
        HttpContext context, CancellationToken ct) => …
}
```

Use it for a conditional `GET`, a webhook, a health check, a redirect, a file download.

**[Start the low-level guide →](./low-level/overview.mdx)**

</div>
</div>

If you are not sure, start high. Dropping a level later changes only the part that did not fit —
which is the point of how the two are built.

## The two levels are one inheritance chain

The high level is not a parallel implementation of the low one. It **is** the low one with its
binding supplied, so the two cannot drift apart:

```
RawEndpoint                              ← low level: you get the context, you return a result
 ├── RawEndpoint<TRequest>               ← middle:    you write BindAsync, the base dispatches
 ├── RawEndpoint<TRequest, TResponse>
 │    └── Endpoint<TRequest, TResponse>  ← high:      the analyzer writes BindAsync for you
 ├── StreamEndpoint<TRequest, TItem>
 └── MappedEndpoint<...>
```

`Endpoint<TRequest, TResponse>` adds exactly one member to `RawEndpoint<TRequest, TResponse>`: a
`BindAsync` that calls the generated binder. `Configure`, `OnSuccess`, the dispatch, the failure
mapping and the OpenAPI metadata are all inherited unchanged from the tier below.

That gives you a middle level worth knowing about: when the request *does* map onto a message but
not by any of the [five binding rules](./high-level/messages.mdx#the-five-binding-rules) — a header that
must be split, one repeated query key becoming a collection — you replace `BindAsync` and keep
everything else.

| Level | What you write | Reach for it when |
|---|---|---|
| `Endpoint<…>` | A class declaration and an attribute | Almost always |
| `RawEndpoint<…>` | `BindAsync` | The request maps onto a message, but not by the five rules |
| `RawEndpoint` | `HandleAsync` | There is no message — the endpoint is about the HTTP exchange |

## Why it exists

Every route in a hand-written Minimal API surface repeats the same four steps: read the inputs, build
a message, call the invoker, map the success response.

```csharp title="Hand-written: the shape repeats once per route"
tasks.MapGet("/{id:guid}", async (
        [FromRoute] Guid id,
        [FromServices] IHttpInvoker invoker,
        CancellationToken ct) =>
    await invoker.InvokeAsync(new GetTaskQuery { TaskId = id }, ct))
    .WithName("GetTask")
    .WithSummary("Get a task by ID");
```

```csharp title="With Endpoints: the shape is generated"
[Get("/tasks/{taskId:guid}")]
public sealed class GetTaskEndpoint : Endpoint<GetTaskQuery, TaskDto>;
```

Nothing is given up in exchange. The status code and response shape stay fully controllable —
[declaratively](./high-level/responses.mdx) for the common shapes, imperatively (`OnSuccess`, `Raw`) for
the rest — and the whole surface is [Native AOT](./reference/native-aot.mdx) clean.

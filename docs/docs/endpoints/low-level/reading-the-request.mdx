# Reading the request

The helpers are extension methods on `HttpContext`, in `UnambitiousFx.Synapse.Endpoints.Binding`. Add
the using and they are all there:

```csharp
using UnambitiousFx.Synapse.Endpoints.Binding;
```

They are the same primitives the high level's generated binders call. That is what makes "the high
level is built on the low level" a fact about the code rather than a claim in these pages — and it
means anything the generated binder can read, you can read the same way.

## The surface

| Member | Returns | Notes |
|---|---|---|
| `TryGetRoute(name, out string?)` | `bool` | Raw string; first value wins when a key repeats |
| `TryGetQuery(name, out string?)` | `bool` | |
| `TryGetHeader(name, out string?)` | `bool` | |
| `TryGetRoute<T>(name, out T)` | `bool` | `where T : IParsable<T>`, parsed with the **invariant culture** |
| `TryGetQuery<T>(name, out T)` | `bool` | |
| `TryGetHeader<T>(name, out T)` | `bool` | |
| `TryGetRouteOptional<T>(name, out T?)` | `bool` | Absent is `true` with a `null` value; only present-but-unparsable is `false` |
| `TryGetQueryOptional<T>(name, out T?)` | `bool` | |
| `TryGetHeaderOptional<T>(name, out T?)` | `bool` | |
| `TryGetRouteEnum<T>(name, out T)` | `bool` | Named separately, not overloaded — see below |
| `TryGetQueryEnum<T>(name, out T)` | `bool` | |
| `TryGetHeaderEnum<T>(name, out T)` | `bool` | |
| `Header(name)` | `string?` | The first value, or `null` |
| `QueryValues(name)` | `StringValues` | **Every** value of a repeated key |
| `HeaderValues(name)` | `StringValues` | **Every** value of a repeated header |
| `BodyAsync<T>(ct)` | `ValueTask<BindResult<T>>` | JSON body; never throws for a client mistake |
| `FormAsync(ct)` | `ValueTask<BindResult<IFormCollection>>` | Reads the form so the synchronous readers below can serve from its cache — call this first |
| `TryGetForm(name, out string?)` | `bool` | Raw string; first value wins when a field repeats. Requires `FormAsync` first |
| `TryGetFormFile(name, out IFormFile?)` | `bool` | One uploaded file. Requires `FormAsync` first |
| `FormValues(name)` | `StringValues` | **Every** value of a repeated form field. Requires `FormAsync` first |
| `FormFiles(name)` | `IReadOnlyList<IFormFile>` | **Every** file uploaded under one field name — not every file on the request, see below. Requires `FormAsync` first |
| `Service<T>()` | `T` | `RequestServices.GetRequiredService<T>()` |
| `Validate()` | `BindingValidator` | [The accumulating collector](./validating) |

The enum readers are named `…Enum` rather than overloaded because two generic methods differing only
in their constraints are a duplicate signature to the compiler (`CS0111`). The `…Optional` readers
*are* overloaded — one `where T : struct, IParsable<T>` and one `where T : class, IParsable<T>` — which
is legal because their `out` parameter differs too: `T?` is `Nullable<T>` in the first and plain `T` in
the second.

## Reading values

```csharp
public override ValueTask<IResult> HandleAsync(HttpContext context, CancellationToken ct)
{
    // Typed, invariant culture. false when absent OR unparsable.
    if (!context.TryGetRoute<Guid>("taskId", out var taskId))
    {
        return ValueTask.FromResult(Results.BadRequest("taskId must be a GUID") );
    }

    // Optional with a fallback of your choosing.
    var page = context.TryGetQuery<int>("page", out var p) ? p : 1;

    // Optional, but still rejecting a value that was sent and is wrong. Absent is true with a
    // null value; only ?limit=abc answers false. Reference types read the same way:
    // TryGetQueryOptional<string> and TryGetQueryOptional<CallbackUrl> both compile.
    if (!context.TryGetQueryOptional<int>("limit", out var limit))
    {
        return ValueTask.FromResult(Results.BadRequest("limit must be an integer"));
    }

    // An enum by name or numeric value.
    context.TryGetQueryEnum<SortOrder>("sort", out var sort);

    // A header, or null.
    var ifMatch = context.Header("If-Match");

    // Every value of a repeated key: ?tag=a&tag=b
    var tags = context.QueryValues("tag").Where(t => !string.IsNullOrWhiteSpace(t)).ToArray();

    // Same, for a repeated header.
    var accepted = context.HeaderValues("X-Accept-Version");

    …
}
```

`QueryValues` and `HeaderValues` are the two that have no direct equivalent at the high level: the
single-value readers take the first value when a key repeats, which is what convention binding
needs, and a hand-written handler frequently wants all of them. A message property typed `T[]`,
`List<T>`, `IReadOnlyList<T>` or `IEnumerable<T>` binds the same repeated values through the high
level — see [Repeated keys](../high-level/messages#repeated-keys) — so a raw `StringValues` loop is
now only needed when the elements need something other than an ordinary parse.

:::note Invariant culture, always
The typed readers pin `CultureInfo.InvariantCulture`, matching ASP.NET Core's own parameter binding. A
route or query value is a wire format — `?amount=1.5` means one and a half regardless of the server's
locale, and it must not mean something different from the identical value on a hand-written `MapGet`
route in the same application.
:::

## Reading the body

`BodyAsync<T>` deserializes the JSON body using the application's configured JSON options, and
**never throws for a client mistake**. Every way the body can be unusable — absent, not JSON,
malformed, or sent with no `Content-Type` — comes back as a failure instead, so a client error stays a
`400` and does not become a `500`.

```csharp
[Post("/webhooks/github")]
public sealed class GitHubWebhookEndpoint : RawEndpoint
{
    public override void Configure(IRawEndpointBuilder builder)
    {
        builder.Accepts<GitHubPushPayload>()
            .Produces(StatusCodes.Status202Accepted)
            .ProducesValidationProblem();
    }

    public override async ValueTask<IResult> HandleAsync(HttpContext context, CancellationToken ct)
    {
        // A webhook payload is someone else's schema, not one of your messages — which is
        // exactly why this endpoint is at the low level.
        var body = await context.BodyAsync<GitHubPushPayload>(ct);
        if (!body.IsSuccess)
        {
            return body.Problem();          // 400 with the failure under the "body" key
        }

        var signature = context.Header("X-Hub-Signature-256");
        if (!SignatureIsValid(signature, body.Value!))
        {
            return TypedResults.Unauthorized();
        }

        await context.Service<IWebhookQueue>().EnqueueAsync(body.Value!, ct);

        return TypedResults.Accepted((string?)null);
    }
}
```

`BindResult<T>` is what comes back: `IsSuccess`, `Value`, `Errors` (keyed by field), and `Problem()`
to turn a failure straight into the `400`. The `ct` you pass is linked with
`HttpContext.RequestAborted`, which applies either way.

:::warning Native AOT
`T` must be registered on a `JsonSerializerContext`. `SYNE008` scans `BodyAsync<T>` call sites written
lexically inside the endpoint class and warns if it is missing — but it cannot follow a body read into
a helper on another type. See [Native AOT](../reference/native-aot).
:::

## Reading a form

`FormAsync` reads `multipart/form-data` or `application/x-www-form-urlencoded` into a cached
`IFormCollection`, the same way `BodyAsync<T>` reads JSON: every way the body can be unusable — no
`Content-Type`, or a malformed multipart body — comes back as a `body`-keyed failure rather than an
exception.

:::warning Read the form first
`TryGetForm`, `TryGetFormFile`, `FormValues` and `FormFiles` are synchronous readers over
`HttpContext.Request.Form`, which only exists once `FormAsync` has populated its cache. Call
`FormAsync` before any of them — skipping it does not throw, it reads an empty form, which is a
quieter failure than an exception and easy to mistake for "the caller sent nothing".
:::

```csharp
[Post("/tasks/{taskId:guid}/attachments")]
public sealed class UploadAttachmentEndpoint : RawEndpoint
{
    public override void Configure(IRawEndpointBuilder builder)
    {
        builder.Produces<AttachmentCreated>(StatusCodes.Status201Created)
            .ProducesValidationProblem();
    }

    public override async ValueTask<IResult> HandleAsync(HttpContext context, CancellationToken ct)
    {
        if (!context.TryGetRoute<Guid>("taskId", out var taskId))
        {
            return TypedResults.BadRequest("taskId must be a GUID");
        }

        var form = await context.FormAsync(ct);
        if (!form.IsSuccess)
        {
            return form.Problem();          // 400 under "body" — not readable as a form at all
        }

        var v = context.Validate();
        v.FormFile("file", out var file);
        v.Form<string>("caption", out var caption);
        if (!v.IsValid)
        {
            return v.Problem();             // one 400 naming every missing field and file
        }

        …
    }
}
```

`FormFiles(name)` reads the files under **one** field name; `context.Request.Form.Files` (an
`IFormFileCollection`) is every file on the request, the same distinction the high level's
`IFormFile[]`/`List<IFormFile>` versus `IFormFileCollection` shapes draw — see
[Messages & binding → Forms and files](../high-level/messages#forms-and-files). Reach for `FormFiles`
when one field can carry several files; reach for the whole collection when the endpoint accepts an
open-ended set of fields.

:::note Declaring the content type is a separate step
None of this declares what the endpoint accepts — that is `Configure`'s job. See
[OpenAPI → Declaring it at the low level](../reference/openapi#declaring-it-at-the-low-level). The
high level does this automatically the moment any message property is form-bound.
:::

## Reaching services

Endpoints are startup singletons, so there is no constructor to inject into:

```csharp
var repository = context.Service<TaskRepository>();
var clock      = context.Service<IClock>();
```

This is `RequestServices.GetRequiredService<T>()` — scoped services resolve per request, as usual.

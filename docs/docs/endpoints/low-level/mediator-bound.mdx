# The middle level: mediator-bound

Between "the analyzer writes everything" and "you write everything" sits the tier most people
actually need when the high level does not fit:

> **The route *is* a message. Only the binding is unusual.**

`RawEndpoint<TRequest, TResponse>` (and `RawEndpoint<TRequest>` for a message with no response) asks
you for `BindAsync` and nothing else. Dispatch, failure mapping, success mapping and OpenAPI metadata
are all inherited.

```csharp
[Get("/reports")]
public sealed class TagReportEndpoint : RawEndpoint<TagReportQuery, TagReportDto>
{
    public override ValueTask<BindResult<TagReportQuery>> BindAsync(HttpContext context)
    {
        // …your binding. Everything downstream of here is identical to Endpoint<…>.
    }
}
```

## What you keep

This is the whole reason to stop here rather than at `RawEndpoint`:

| | Inherited? |
|---|---|
| Dispatch through `IHttpInvoker` | ✅ |
| `IFailureHttpMapper` for handler failures | ✅ |
| `400` from a bind failure, `HttpValidationProblemDetails` | ✅ |
| `Configure(IEndpointBuilder<TResponse>)` — `Ok`, `Created`, `NoContent`, `StatusCode`, … | ✅ |
| `OnSuccess(TResponse, HttpContext)` | ✅ |
| `Accepts`/`Produces` metadata from the type arguments | ✅ |
| Binding | ❌ — that is what you are here to write |

`Endpoint<TRequest, TResponse>` differs from this class in **exactly one** respect: it takes its binder
from the generated registry instead of asking you for one. So dropping to this tier changes only the
binding, and nothing else about the endpoint's behaviour moves.

## When to drop here

| Situation | Why the five rules cannot do it |
|---|---|
| `?tag=a&tag=b` becoming a collection | Convention binding takes the first value of a repeated key |
| A header that must be split or parsed further | The value reaches you as one string |
| A legacy query-string shape (`filter=name:asc,age:desc`) | No rule maps one key onto several properties |
| A value that needs normalising before it is part of the message | Binding has no hook between read and construct |
| The message must come partly from a claim or the connection | Not part of the request's route/query/header/body at all |

## A worked example

`?tag=a&tag=b` becoming an `IReadOnlyList<string>` — none of the five rules can express it, and
nothing else about the endpoint needs to change:

```csharp title="The message and its handler are completely ordinary"
public sealed record TagReportQuery(int Page, int Size, IReadOnlyList<string> Tags)
    : IRequest<TagReportDto>;

public sealed record TagReportDto(int Page, int Matched, IReadOnlyList<string> Tags);

[RequestHandler<TagReportQuery, TagReportDto>]
public sealed class TagReportQueryHandler : IRequestHandler<TagReportQuery, TagReportDto>
{
    private readonly TaskRepository _repository;

    public TagReportQueryHandler(TaskRepository repository)
    {
        _repository = repository;
    }

    public ValueTask<Result<TagReportDto>> HandleAsync(
        TagReportQuery request,
        CancellationToken cancellationToken = default)
    {
        var matched = _repository.GetAll()
            .Count(task => request.Tags.Any(tag =>
                task.Title.Contains(tag, StringComparison.OrdinalIgnoreCase)));

        return ValueTask.FromResult(Result.Success(
            new TagReportDto(request.Page, matched, request.Tags)));
    }
}
```

```csharp title="Only BindAsync is hand-written"
[Get("/reports")]
public sealed class TagReportEndpoint : RawEndpoint<TagReportQuery, TagReportDto>
{
    // Inherited, and identical to what Endpoint<…> would give you.
    public override void Configure(IEndpointBuilder<TagReportDto> builder)
    {
        builder.Tag("Ops")
            .Summary("Report on tasks matching any of the given tags");
    }

    public override ValueTask<BindResult<TagReportQuery>> BindAsync(HttpContext context)
    {
        var v = context.Validate();

        v.QueryOptional<int>("size", out var size);

        if (v.Query<int>("page", out var page))
        {
            v.Check(page >= 1, "page", "must be at least 1");
        }

        var tags = context.QueryValues("tag")
            .Where(static tag => !string.IsNullOrWhiteSpace(tag))
            .Select(static tag => tag!)
            .ToArray();

        v.Check(tags.Length > 0, "tag", "at least one tag is required");

        return ValueTask.FromResult(v.IsValid
            ? BindResult<TagReportQuery>.Success(new TagReportQuery(page, size ?? 20, tags))
            : BindResult<TagReportQuery>.Failure(v));
    }
}
```

Note what is *not* in that file: no dispatch, no `IHttpInvoker`, no failure handling, no `200 OK`. All
inherited.

## Returning a failure

`BindAsync` returns `BindResult<TRequest>`. A failure short-circuits to `400` carrying every collected
error, and the message is never dispatched.

```csharp
// From the collector — every problem it gathered.
return ValueTask.FromResult(BindResult<TagReportQuery>.Failure(v));

// Or one specific problem, keyed by field.
return ValueTask.FromResult(
    BindResult<TagReportQuery>.Failure("tag", "at least one tag is required"));
```

## Reading the body here too

`BindAsync` is `async`-friendly, so a body read is fine:

```csharp
public override async ValueTask<BindResult<ImportCommand>> BindAsync(HttpContext context)
{
    var body = await context.BodyAsync<ImportPayloadDto>();
    if (!body.IsSuccess)
    {
        return BindResult<ImportCommand>.Failure("body", "The payload could not be read.");
    }

    var tenant = context.Header("X-Tenant") ?? "default";

    // Normalise on the way in — the hook convention binding does not have.
    return BindResult<ImportCommand>.Success(new ImportCommand(
        Tenant: tenant.Trim().ToLowerInvariant(),
        Rows: body.Value!.Rows.Where(static row => row.Length > 0).ToArray()));
}
```

## `Configure` has one sealed member

This tier configures through the typed `Configure(IEndpointBuilder<TResponse>)`. The low-level
`Configure(IRawEndpointBuilder)` overload is **sealed**, so overriding it is a compile error rather
than a silent no-op — that hook is never called at this tier, and a subclass overriding it would
otherwise wonder why its configuration is ignored.
